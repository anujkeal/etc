# ETC DOCUMENTARY SCRIPT — REQUIRED OUTPUT FORMAT

Use this format for every completed script. Adapt the number of chapters to the subject and duration. Do not force a fixed number of sections.

# 1. PROJECT OVERVIEW

- **Target duration:**
- **Estimated narration word count:**
- **Audience:**
- **Central question:**
- **One-sentence premise:**
- **Viewer takeaway:**
- **Narrative approach:**
- **Scope and exclusions:**

# 2. RESEARCH BRIEF

Summarise the verified knowledge needed to understand the documentary.

Include:
- Key concepts and definitions.
- How the mechanism or event works.
- Important context.
- Misconceptions to avoid.
- Important limitations and uncertainties.
- The most useful real example or demonstration.

Do not turn this section into the narration. It is the factual foundation for the script.

# 3. SOURCE REGISTER

| ID | Source title | Author/organisation | Publication/update date | URL | Claims supported |
|---|---|---|---|---|---|

Use exact, verified source details. Identify inaccessible or uncertain sources honestly.

# 4. NARRATIVE OUTLINE

| Time | Chapter | Narrative purpose | Question answered | Transition |
|---|---|---|---|---|

The outline must have a clear beginning, development, and resolution.

# 5. COMPLETE SCRIPT AND VISUAL TIMELINE

Use the following scene format repeatedly:

---

## SCENE 01 — [Short descriptive title]

**Timestamp:** 00:00–00:35  
**Narration:**

Write the exact words intended to be spoken. This must be polished, natural, original narration, not notes or bullet-point talking prompts.

**Visual direction:**

Describe the visual sequence in practical editing terms. Explain what appears, what moves, what changes, and what the viewer should understand.

**On-screen text:**

Only essential labels, figures, code, names, or short phrases. Write "None" when no text is needed.

**Sound design:**

Specify music, ambience, effects, or intentional silence only when they serve the scene.

**Research references:**

List the source IDs supporting the factual claims in this scene, such as C01, C02. These IDs must map to the research ledger and source register.

---

Continue for all scenes. Timestamps must be sequential, plausible, and aligned with the target runtime.

### Script rules

- Narration must be complete and ready to record.
- Do not place research notes inside spoken narration.
- Keep visual directions separate from narration.
- Use scene changes when the idea or visual purpose changes.
- Avoid excessive on-screen text.
- Do not suggest a visual that contradicts the actual mechanism.
- Use exact code or technical labels when demonstrating them.
- If a visual is conceptual rather than literal, label it as a conceptual visualisation.
- If the scene contains a real-world interface or product, identify the version or context when relevant.

# 6. ENDING

Include the final narration and visual resolution. Explicitly show how the ending answers the central question from the opening.

# 7. FACT-CHECK REPORT

| Claim ID | Scene | Status | Notes or correction |
|---|---|---|---|

Statuses:
- Verified
- Verified with qualification
- Needs further verification
- Removed

No important unsupported claim should remain in the final narration.

# 8. EDITORIAL NOTES

Briefly list:
- Important simplifications made.
- Disputed or uncertain points.
- Any scope limitations.
- Visuals requiring technical review.
- Any source that should be checked again before publication.

# 9. FINAL RUNTIME CHECK

Report:
- Total estimated narration words.
- Assumed narration speed.
- Estimated spoken duration.
- Estimated visual-only pauses and transitions.
- Estimated final runtime.
- Whether the requested duration is realistic.

Never claim exact runtime from word count alone. The final edit and actual narration speed determine the real duration.
